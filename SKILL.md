# YouTube Creator Intelligence Hub

## Invariants

- Global Fact Layer stores reusable Creator / Video / Snapshot / Discovery / Job / AI evidence facts.
- Workspace Intelligence Layer owns brand, taxonomy, relationship, commercial metric, discovery profile, rules and saved views.
- Core must not introduce fixed customer, brand or industry semantics. Domain compatibility belongs in `creator_hub/compat/` or Workspace templates.
- Effective-value precedence remains `human > ai > derived > fact`; provenance and audit must be preserved.
- Long-running work uses the persistent Job Engine. Resumable jobs require durable checkpoint writes; persistence degradation is surfaced, never silently ignored.
- Schema changes use the Migration Runner. Never edit an existing business SQLite schema manually.
- Single-row and batch actions must remain semantically consistent.
- New integrations use the typed FastAPI `/api/v1` surface. The default Dashboard must remain domain-neutral; compatibility semantics are opt-in and must not leak into generic Workspaces.
- Creator Discovery is topic-agnostic by default. Query Expansion, saved Query Profiles, discovery filters/exports, search placeholders and AI Query Planning must not assume games, cloud-phone use cases or any other vertical unless the active Workspace or user explicitly supplies that domain.
- Public Query Packs use Workspace-scoped schema 4 / `generic_creator_discovery_v2`. Query Pack groups are editable strategy objects; normal upgrades must preserve user-defined groups, names, descriptions, order and per-language vocabularies. The 4.3 profile is migrated with user term edits retained.
- Production databases, API keys, exports, backups, caches and logs never enter Git.

## Routing

- Interactive existing Dashboard: `python hub.py serve` or `start-dashboard.cmd`.
- Typed API / OpenAPI: `start-api.cmd`, Swagger at `http://127.0.0.1:8766/docs`.
- Synthetic public demo: `create-demo.cmd`, then `start-demo.cmd`.
- Benchmark: `run-benchmark.cmd` or `python -m creator_hub.portfolio.benchmark`.
- AI evaluation: `run-ai-eval.cmd` or `python -m creator_hub.portfolio.ai_eval`.
- Repository engineering checks: `pytest`, `ruff check creator_hub/api creator_hub/portfolio creator_hub/compat creator_hub/jobs.py creator_hub/monitoring.py creator_hub/field_registry.py creator_hub/ai/local_tools.py tests scripts/check_core_portability.py scripts/check_public_surface_neutrality.py scripts/neutralize_public_surface.py scripts/neutralize_discovery_surface.py scripts/query_pack_editor.py scripts/repo_hygiene.py`, `python scripts/check_core_portability.py`, `python -m scripts.check_public_surface_neutrality`.

## Creator workflows

Discovery candidates and the formal Creator library remain separate. Preserve Discovery Run / Hit / Creator Result provenance. Do not automatically full-history capture every discovered candidate.

Country evidence order remains: YouTube About > YouTube API > metadata keyword > language hint. Public contact collection must not bypass CAPTCHA or platform verification.

## AI rules

AI is optional. It must use local evidence, return structured outputs, retain evidence references, and never fabricate missing content-fit, audience-fit or brand-safety inputs. Run specifications freeze repeatable AI/discovery conditions. Use `evals/` for grounding evaluation before publishing model quality claims.

## Portfolio/public-repo rule

Use only synthetic demo data in public demonstrations. Performance or AI-quality numbers must be generated by the included benchmark/evaluation harness and accompanied by the machine/model configuration. Never invent benchmark numbers.

## Query Pack Editor (4.4.0)

Query Expansion groups are Workspace-scoped editable strategy objects. Users can rename and describe groups, enable/disable them, add/delete/duplicate/reorder groups, edit per-language terms, restore one system group, restore the current language defaults, or restore the full system catalog. User-defined groups are stored in the Workspace `query_profile` and are not overwritten by normal upgrades.
